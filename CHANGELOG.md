# Changelog

Notable project changes are recorded here. Versions follow Semantic Versioning, and release notes follow Keep a Changelog.

## [Unreleased]

### Added

- Add account erasure by anonymisation in place (audit F-041; `apps/users/services/erasure.py`). `users` owns the orchestration: a staff dialog "Erase account" (permission `users.anonymize_account`, reason and typed phrase) and a self-service page `/users/account/erasure/` (password, verified email, one-time emailed link, 14-day grace period, cancel any time; settings `ACCOUNT_ERASURE_GRACE_DAYS`, `ACCOUNT_ERASURE_MAX_ATTEMPTS`, `ACCOUNT_ERASURE_BLOCKED_MAX_DAYS`) run the same atomic, idempotent service: identity and credentials are scrubbed (`erased-<id>@erased.invalid`, unusable password, inactive, `CustomUser.anonymized_at`), profile, follows, activity, notifications, push, security question, MFA, email addresses, social accounts, API tokens and stored sessions are deleted, admin history text is blanked, and every other app is asked through `AppService` exports (`erasure_blockers(user)`, `anonymise_user(user)`; wallet already implements them, the rest are reported as gaps and end the request as "partial"). Failures roll everything back and are retried a bounded number of times; blockers wait without using attempts and fail terminally after 30 days. Tombstone/audit table `AccountErasure` (counts only, no personal data), Celery task `users.process_account_erasures` and `manage.py process_account_erasures`. Migration `users/0008_account_erasure`.
- Gate every sign-in on the device policy through one seam (audit F-004; `apps/users/services/device_gate.py`): web password, MFA completion, every allauth login (social callback, email link, email code, sign-up) via `CustomAccountAdapter.login`, API password and Google token; the devices contract is reached only through `AppService`, an installed-but-broken contract fails closed and a missing devices app enforces nothing.
- Users hardening from the app audit: the profile-completion gate can no longer be skipped with `HX-Request`/`X-Requested-With`/JSON headers (F-028: HTMX gets `HX-Redirect`, AJAX/JSON gets a 403 JSON body); TOTP codes and recovery codes are single use under concurrency (F-035: a conditional UPDATE of the last used time step, a locked re-read for recovery codes); staff MFA also binds the API sign-in and the disable action (F-015); the social provider/posting APIs need the per-model permissions and never echo exception text; profile and password forms validate input, rate limit the current-password check and revoke API tokens on a password change; limiter keys and IPs no longer reach the logs; the contribution list queries once per category and the notification list is paginated.

- Harden the credits ledger (audit F-020, F-041; `apps/wallet`, `wallet-economy.md`). Model guards: ledger rows are insert-only (a save that reuses a primary key is refused; queryset `bulk_create`/`bulk_update` raise too) and `Wallet.balance`/`held` can only be written inside `ledger_posting()`, so `Wallet.objects.update(balance=…)` and a stale full `wallet.save()` are refused. Migration `wallet/0003_ledger_integrity` adds CHECK constraints (ledger direction and key, non-negative top-up/payout money, payout fee 0-100), indexes for the cap/cooldown and reconcile queries, the append-only `WalletRepair` audit model and, on PostgreSQL only, a reversible `BEFORE UPDATE/DELETE` trigger that refuses any change to a ledger money column (`note` changes only in the erasure window, `actor` can only be cleared). `reconcile()` (read-only) compares every wallet's balance, held credits and last `balance_after` with the ledger and open escrow holds, re-checking under the row lock; `manage.py reconcile_wallets [--deep] [--fail-on-drift]`, the Celery task `apps.wallet.tasks.reconcile_wallets` (time limited, structured `alert=wallet_reconcile_drift` ERROR logs) and the explicit audited `manage.py repair_wallet` (dry run by default, permission, reason and idempotency key). Account erasure contract `apps.wallet.api.erasure_blockers` / `anonymise_user` scrubs personal text around the ledger and keeps every amount and balance. New `reward_rules()` read-only contract.
