## Current suite inventory

The root suite is collected from `tests/backend/<app>/` (grouped by owning app, with cross-app contracts in `tests/backend/integrations/`, plus the root-level boundary, template-inventory, frontend-contract and URL-smoke checks) and `tests/frontend/` (Playwright browser checks). Counts change with every wave; get them from `pytest --collect-only -q` and `scripts/application_map.py`, not from this document. Several apps still have partial coverage. Treat the gaps above as open quality work; do not close them without focused tests and a product-approved acceptance map.

All automated test discovery is rooted in `tests/backend/` and `tests/frontend/`. No application-local test directory is authoritative. The public and admin shells are rendered from the Django templates under `templates/` and each app's `templates` directory; browser-visible rendering is covered by the Playwright checks above, and final visual calibration remains a product/design review item.

## Change rule

For each new requirement, record an ID, owning app, acceptance criterion, and specific test before implementation. Update this map when tests or scope change. A whole-suite pass does not replace requirement-level evidence.
