# Feature Catalog (Code-Derived Draft)

The catalog inventories capability families visible in the installed code. It is not a complete feature specification, and all product scope remains unapproved. Test mappings indicate existing evidence, not comprehensive coverage.

| ID | Capability family | Owning app | Current evidence | Test evidence |
| --- | --- | --- | --- | --- |
| REQ-USR | Account, profile, following, activity, notification, and security workflows | `users` | User routes, account model, profile/social models and notification services | `tests/backend/users/test_users.py` (partial) |
| REQ-DEV | Device identity, per-user device records, device events, and policy enforcement | `devices` | Device services, policy settings, device APIs and login signal | `tests/backend/devices/test_devices.py` (registration and login-policy paths only) |
| REQ-ADS | Ad delivery, consent-aware events/clicks, rewarded ad settings, and affiliate products | `ads` | Ad/affiliate models, API routes and services | `tests/backend/ads/test_ads.py` (partial) |
| REQ-BLOG | Editorial posts, publication workflow, feeds, search, and related content | `blog` | Post/category models, views, feeds, automation and the `blog.services.workflow` status workflow | `tests/backend/blog/test_tagging_integration.py`; `tests/backend/blog/test_post_workflow.py` |
| REQ-COM | Comment submission, visibility, reporting, voting, and moderation | `comments` | Comment model, routes, moderation services (`comments.services.decisions`) | `tests/backend/comments/test_comments.py`; `tests/backend/comments/test_comment_decisions.py` |
| REQ-FW | Firmware catalog, chipsets, upload/external submission and staff review, generic gated downloads, hotlink checks, changelogs, guides, and automated brand/model/chipset blog posts | `firmwares` | Firmware models, services, APIs, routes, blog automation | `tests/backend/firmwares/`; `tests/backend/integrations/test_firmware_blog_inventory.py` |
| REQ-TAG | Tag assignment, lookup, discovery, merging, and curation | `tags` | Tag and generic tagged-item models, services, views and automation | `tests/backend/tags/` (service/regression coverage; UI/API coverage incomplete) |
| REQ-MOD | App-owned moderation decisions (firmware approve/reject/withdraw, post workflow, comment decisions, tag approval) with reviewer/time/reason recorded; the former governance app was removed | `firmwares`, `blog`, `comments`, `tags` | Services and admin actions in each owning app | `tests/backend/firmwares/test_moderation_services.py`, `tests/backend/firmwares/test_admin_review.py`, `tests/backend/blog/test_post_workflow.py`, `tests/backend/comments/test_comment_decisions.py`, `tests/backend/tags/test_tag_admin_actions.py`, `tests/backend/integrations/test_governance_app_removed.py` |
| REQ-CORE | Shared platform support, health endpoints, and scoped retention command | `core` | Settings/services, `/health/live/`, `/health/ready/`, cleanup command | `tests/backend/core/test_core.py` (retention behavior only) |
| REQ-REL | Application release metadata and editorial content history/restore | `app`, `blog` | Package metadata is surfaced in public/admin shells; draft-only restore uses the existing `PostRevision` model | `tests/backend/core/test_release_metadata.py`, `tests/backend/blog/test_versioning.py` |
| REQ-SET | Runtime, admin-editable site settings: identity/branding, contact/social/share defaults, localization, maintenance and HTTPS, email credentials (encrypted, write-only), reCAPTCHA, verification-code shape, firmware download gate, analytics IDs, verification meta tags/files | `site_settings` | `SiteSettings` singleton, cached accessor `apps.site_settings.services.get_site_settings`, context processor, maintenance/locale/analytics-CSP middleware, `/site/info/`, `/site/verification/<name>/`, Unfold admin (see `../04-backend/site-settings.md`) | `tests/backend/site_settings/` |

Do not mark a capability complete from this table alone. Expand each family into approved user scenarios and acceptance criteria before implementation or release.
