# Requirements Analysis

## Goal

Translate user intent into testable, approved requirements while keeping proposals distinct from implementation facts.

## Steps

1. Identify user, actor, trigger, expected result, failure behavior, authorization, and data lifecycle.
2. Map each requirement to an owning app and real current entry point.
3. Define observable acceptance criteria and the smallest useful regression/contract tests.
4. Mark unresolved product, permission, frontend, retention, and external-provider decisions as requiring owner approval.
5. Check for conflicts with existing approved docs and source-of-truth rules.

## Output

Use stable requirement IDs and trace each to code/test evidence. Do not claim the current draft PRD is approved.
